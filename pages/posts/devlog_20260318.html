When working on any websites, you'll generally have to convert and compress a lot of media files. I don't know how other people do it but for this I recommend familiarising yourself with `image magick` and `ffmpeg` :3 These afford you a lot of control over manipulating images, videos and audio and because they're commandline tools, they're very easy to automate.

cd media; cat gifs_suck.md

Take the following gifs I have on the DOOM2 Shrine. Their size, considering their length and quality is laughable.. With limited space on neocities, let's convert and compress them (they were captured as gifs so there's not much more quality to be lost lmao).

ls *.gif | each {|| $in | insert duration {
    ffmpeg -i $in.name o+e>
		| grep Duration
		| cut -d ' ' -f 4
		| sed s/,//
  }}

cat ffmpeg_basic_conversion.md

This is the basic structure of the ffmpeg command I use for converting and compressing webms.

convert gif to webm with not so good quality
ffmpeg -i file.gif -c:v libvpx-vp9 -b:v 0 -crf 40 output.webm
  • -c specifies the encoder to use.
    • libvpx can save ~20-50% bitrate compared to libx264 without much/any perceivable quality loss.
    • also has good browser support.
  • -b specifies target bitrate. this is variable bit rate however we can set it to 0 to use constant bitrate and specify the quality via the -crf option or if we specify both with a non-zero bitrate, the -b value is used as a constraint target.
  • -crf specifies the quality

Of course, this can be automated with your shell or scripting language of choice :3

convert all gif in dir to webm 
ls -t *.gif
	| each {|path| $path.name | path parse } # parse so we can reuse the name
	| each {|file| ^ffmpeg -i $"($file.stem).($file.extension)" -c:v libvpx-vp9 -b:v 0 -crf 40 $"($file.stem).webm" }
ls -t *.gif *.webm | sort-by modified -r

As you can see, the webms are a fraction of the size and, in this case at least, no worse off quality-wise. If you were converting a higher quality source, you'd of course use higher bit rate and/or quality but as I said, these gifs were already crusty lmao. I just wanted the smaller file size.

Speaking of, you can use the same command to compress as well.

note the matching file extensions.
ffmpeg -i file.webm -c:v libvpx-vp9 -b:v 500k -crf 28 output.webm

All of the above is probably fine for basic stuff like this, however the docs recommend doing two-pass with libvpx for quality-enhancing features.

care: piping to null varies across shells 
ffmpeg -i input.mp4 -c:v libvpx-vp9 -b:v 2M -pass 1 -an -f null /dev/null && \
ffmpeg -i input.mp4 -c:v libvpx-vp9 -b:v 2M -pass 2 -c:a libopus output.webm
